1 · Executive summary & philosophy

Locate the gain before crediting the ontology

A "with ontology versus without" comparison treated as a black box cannot tell whether a gain came from better prose definitions, which a SQL comment or data catalog could also carry, or from semantic graph capabilities: subclass reasoning, encapsulated join paths, closed-world validation and empirical partition metadata.

The opposite mistake is as costly. v1's weak grounding recall was first attributed to missing definitions (172 of 220 mapped terms had none). Enriching them to 216 of 220 moved recall by less than one point. The real loss was the vocabulary gap between business phrasing ("company name", "bought") and formal labels (RESULTS.md §5.1).

The framework sets out to

  1. Isolate each semantic layer with a ladder of arms that changes one factor per rung.
  2. Split the runtime into six ports with oracle adapters that bound the loss at each stage.
  3. Check the ontology and data at build time: must-pass checks gate LLM spend; reported checks never block.
  4. Score SQL and SPARQL arms on one execution and safety yardstick across seven database instances.

Its conclusions are protected by

  • a pre-registered analysis plan: primary hypothesis, gold-query cluster bootstrap, minimum detectable effects, Holm correction (§5.5);
  • contamination controls: glossary quarantine, blind transfer mapping, obfuscated schema, fresh paraphrases (§4.5);
  • reproducibility pins on every run: model snapshot, program, pack and data hashes.
2 · The semantic ladder

4.2 The discriminative instance suite: Base + V1–V6

Scoring on Base alone is invalid: 96 of 237 gold queries return empty sets there, and base relaxed EX (48–62%) more than doubles suite accuracy through empty-versus-empty matches. Every query is scored on seven instances, each with its gold answer recomputed by running the gold SQL on it. Every instance must have zero dangling keys, because Ontop trusts declared keys for join elimination.

V5 repair (V3.1). The v1 witness builder left 1,570 subclass rows without their parent rows, breaking 4 subclass keys (e.g. 685 ListedSecurity rows with no Security row). The builder now adds the parent chain (2,255 rows). The repair left the ceiling unchanged at 219/237 and moved executable-mutant detection from 58.3% to 58.5%. Rescoring the v1 live runs on the repaired V5 is in progress.

What V6 showed. V6 changes the gold answer of 63 queries, and all 219 accepted gold queries still agree on it. But 199 of the 218 v1 superclass mutants are equivalent under the declared keys: the swapped variable is reached through a key that targets the subclass (HOLDING.REFERSTO → LISTEDSECURITY), so no valid instance can tell the two queries apart. v1's "9 of 218 caught" measured the schema, not the test suite. Superclass detection is now reported on the 19 non-equivalent swaps (8 of 18 executable with non-empty gold).

Gate 2 · Component metrics stage S4

  • Oracle sources. Gold terms, edges and filter values are extracted automatically from accepted gold SPARQL. Gold mention spans need human annotation (annotator, date, agreement on a 20% double-annotated sample). Until then the C1 oracle uses verbatim value spans and is labelled partial.
  • Retrieval (C1 + C2): concept recall@k for k = 5, 10, 20 and MRR; value-linking F1 on (value, owning property) pairs.
  • Pruning (C3): an equivalence-aware grounding ceiling. A term set counts if it covers the gold terms up to equivalences this data makes true, or if a query built from it passes the suite. Edge precision is reported with the subgraph's token count.
  • Refusal gate (C4): recall per U stratum; false-refusal rate on answerable questions; precision at the split's mix and at a fixed 20% prevalence (target ≥ 0.90).

Validation split, single run: 5 runs × 87–123 questions × ~US$0.02 ≈ US$9–13. Differences between consecutive runs are ceilings along one path, not an additive decomposition: a component's loss depends on what upstream hands it. The largest drop says where to look first. GEPA is applied to that module, and comparison arms receive the same optimisation budget.

Gate 4 · End-to-end execution, safety and economics scoring ready

Accuracy

  • Strict and relaxed base EX (relaxed allows omitting the gold's extra context columns)
  • Suite relaxed EX: correct on every instance (headline)
  • Ceiling-normalised suite EX on the questions inside the compiler ceiling; SQL arms on the same subset

Safety and economics

  • Four exclusive outcomes: correct, wrong-but-executed, refused, failed
  • Wrong-but-executed rate (headline safety metric; target ≤ 2%)
  • Run-to-run stability over 3 runs (≥ 90%); P50/P95 latency per port; $/question, $/correct, tokens/question; curation hours
Utility(c) = (1/N) Σ [ +1·SuiteCorrect − c·WrongExecuted + 0.3·CorrectRefusal − 0.3·FalseRefusal ], c ∈ {1, 2, 5}

The abstain-on-everything floor is 0.3·(|U| − |A|)/N, which is negative on a mostly answerable split. It is printed per split, and the four components are always shown next to the total.

5.5 Statistical analysis plan (pre-registered)

ElementRule
Primary hypothesis H1On the FIBEN test split, L3 has a lower wrong-but-executed rate than L1.
Secondary, Holm-corrected in orderH2: L3 suite EX non-inferior to L1 (margin 5 pp) · H3: L1.5 − L1 > 0 on the hierarchy slice · H4: L3 refusal recall on U2 > L2. Everything else is exploratory.
Unit of analysisGold query. Confidence intervals resample gold queries (10,000 resamples) and carry all their paraphrases. Question-level bootstraps are not reported.
Repeated runs3 runs per arm. McNemar on per-question majority outcomes; the bootstrap resamples runs within each question. Runs are never pooled as independent questions.
PowerMinimum detectable difference reported with every comparison. At ~30% discordance: ≈ 19 pp on val (n = 63), ≈ 14 pp on test (n = 117). Reaching 5 pp needs ≈ 800 questions. Below the MDE, a non-significant result reads "not detected", never "no difference".
Equal optimisationFixed prompts for ladder comparisons; optimised rows only with equal GEPA budgets.
PinsModel snapshot and decoding; DSPy, LiteLLM, Ontop, sqlglot, DuckDB versions; prompt, pack, ontology, mapping and gold hashes; split and seed. Without pins a result is not reportable.

7 · Governance

Go / no-go on the frozen test split

Value of the ontology proven

  • H1 holds with Holm-corrected p < 0.05, and L3 also beats L0 on wrong-but-executed.
  • H2 holds (accuracy non-inferior).
  • Hierarchy and obfuscated-schema slices point the expected way.
  • Contamination controls passed: Gtrain only, paraphrase drop reported, BIRD mapping committed first.

Productisation thresholds

  • Ceiling-normalised suite accuracy ≥ 85%
  • Wrong-but-executed ≤ 2%
  • Refusal recall ≥ 0.80 per stratum; precision ≥ 0.90 at 20% prevalence
  • BIRD transfer drop ≤ 15 pp; stability ≥ 90%
  • P95 ≤ 10 s; ≤ US$0.05 per question
  • Full provenance logged; no database rows sent to the model
