Orchestrator from models

The running workbench is generated, not hand-wired. This is what "ASE is modelled in ASE" means in code.

  1. orchestrator.self_model() reads ase-system.sysml and ase-evolution.sysml together.
  2. topology(increment) takes the AseWorkbench<inc> part usages as nodes, its flows as edges, finds back edges by DFS, and reads maxIterations.
  3. build(increment, steps) maps each usage to a registered step function (a missing one raises KeyError), adds forward edges, and turns each back-edge tail into a conditional edge that retries while rec.rework is set and passes < maxIterations.
  4. realises(increment) reads @Realises metadata so every trace folder is labelled with its IDEF0 activity.

What cli selftest asserts

#Assertion
1Gate: ase-system.sysml, ase-evolution.sysml and both together pass the structural gate
2Aggregates: each agent's declared calls, latency and tokens equal the analysis of its pipeline (HierarchyGap, checked by hand until I3)
3Sweep: no error-severity finding on the self-model
4Orchestrator: for each built increment (only I0), the compiled graph's edges equal the model's topology
5Realises: every part of every AseWorkbenchI* has exactly one activity in A1 to A8, MECH or R1

Adding a step means: add the part and flow to ase-evolution.sysml, add its @Realises entry, register the function in pipeline.STEPS, and selftest must still pass.

RunRecord (pipeline.py) carries run and project ids, intake results, selection, design path and gate verdict, analysis and verdicts, findings, graph counts, program path, eval metrics, steps_run and errors. Underscored fields (_spec, _design_model, _module, …) are runtime-only and not serialised.

Analysis and checks

analysis.analyse_pattern computes a pattern's properties from declared stage estimates:

  • Cycles: back edges found by DFS; cycle members are multiplied by maxIterations.
  • Fan-out: multiplies the cost of everything downstream.
  • Latency: critical path over the DAG of forward edges.
  • Verdicts: LatencyBudget, CostBudget, GroundedAnswer (provenance on every retrieval-to-answer path), BoundedLoop. Labels: satisfied, CLAIMED BUT FAILS, holds unclaimed, correctly unallocated.

kg.project() builds a separate in-memory check graph joining design and methodology; checks.py registers 34 checks across 13 perspectives; workflow.walk() runs them in the methodology's order (Context, Functional, Information, Knowledge, Concurrency, Autonomy, Deployment, Operational, Development, then the perspective sweep). A check that raises becomes a warning finding rather than crashing the run.

python -m sysmlagents.selftest (not the CLI command) proves every check can fire, using models/tripwire.sysml, a deliberately defective design.

Evaluation today

  • Questions: five placeholders, one per functional requirement plus an out-of-corpus question ("What is the weather like on the moon?").
  • Corpus: <project>/inputs/corpus/*.txt split on blank lines; otherwise the spec's own sentences, labelled as placeholder.
  • Retrieval: word overlap, top 3, bound into IMPLEMENTATIONS by runtime_stub.bind.
  • Model: offline DummyLM with a canned answer citing the first chunk; online dspy.LM(SYSMLAGENTS_MODEL).
  • Metric: one, groundedness (citations non-empty and all among retrieved ids), traced to the first grounding requirement.
  • Outputs: design/eval/eval-report.json, eval-report.md, questions.json. No optimisation is run.

Known limits and drift

Code issues worth fixing

  • Provider coupling. configure_lm decides offline/online on OPENAI_API_KEY only; agent.py imports langchain_openai directly; requirements.txt names an llm.py that doesn't exist. Plan item 0.8 (provider-agnostic model layer) is not started.
  • Parallel branches. RerankHybridRag and AgenticRag programs crash with a LangGraph concurrent-update error. A fan-in fix exists in PR #1.
  • New state keys are dropped. RagState has no verdict key, so LangGraph discards it: in CorrectiveRag the web fallback always runs. Any new stage output (entities, subgraph) must be added to the state schema.
  • Loop bound not enforced. _branch increments iteration inside a routing function, which LangGraph does not persist; an always-ungrounded SelfRag hit GraphRecursionError after 3,334 calls instead of stopping at 3.
  • Token budget stop never fires. Generated programs initialise spent_tokens but never increment it.
  • run_graph recompiles the graph for every question.
  • The Run node id uses the start timestamp, not the run id (pipeline.py:205).
  • spec._derive_budgets checks a key that is never set in the minutes branch (spec.py:156).
  • The offline DummyLM cites the first chunk for every question, so groundedness 0.40 measures retrieval overlap, not answer quality.
  • The materialiser runs twice per run; the second pass is untraced as its own step.

Documentation drift

  • 36 checks in ase-system.sysml, README.md and the roadmap; 34 in code.
  • The MCP server docstring says eight tools; there are 11. The selfmodel docstring says five assertions, then four.
  • The I0 @Delta still names designs/<spec>/design.sysml; runs now write to <project>/design/.
  • examples/RS-01/ predates projects: its run.json has no project or run id.
  • IDEF0 agent names (ConsolidationAgent, ViewAuthoringAgent) differ from the system model (IntakeAgent, DesignAgent).
  • The Deployer is in the roadmap but not yet in either model.
  • docs/ase-architecture.html was generated on 21 September 2026, before the evolution model last changed (12 October).
