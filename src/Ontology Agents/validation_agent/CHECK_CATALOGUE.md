## SYN

**Syntax & well-formedness.** Can the document be read at all, and are its terms and literals lexically valid?

| id | check | sev. | method | adj. | applies | stage | mutation |
|---|---|---|---|---|---|---|---|
| SYN-01 | **Document does not parse** | blocker | parse | none | all | S1a | truncate-statement |
| SYN-02 | **Invalid IRI** | major | parse | none | all | S1a | inject-space-in-iri |
| SYN-03 | **Ill-typed literal** | blocker | parse | none | all | S1a | corrupt-typed-literal |
| SYN-04 | **Malformed language tag** | minor | parse | none | all | S1b | corrupt-language-tag |
| SYN-05 | **Malformed RDF list** | blocker | sparql | none | owl | S1b | break-rdf-list |
| SYN-06 | **Malformed restriction** | blocker | sparql | none | owl | S1a | drop-onProperty |
| SYN-07 | **IRI contains file extension** | minor | lexical | none | all | S1b | add-file-extension |
| SYN-08 | **Empty or padded literal** | minor | lexical | none | all | S1b | blank-label |

- **SYN-01** -- The submission fails to parse in its declared or sniffed serialisation. *Why:* Nothing downstream is meaningful; report the parser position and stop the run.
- **SYN-02** -- IRIs containing spaces, illegal characters, or relative IRIs without a base. *Why:* Invalid IRIs are silently rewritten or rejected by different tools, so two stores disagree on what the ontology says.
- **SYN-03** -- A typed literal whose lexical form is outside its datatype's lexical space (e.g. "abc"^^xsd:integer). *Why:* In OWL 2 DL an ill-typed literal makes the ontology inconsistent; most authors do not know that.
- **SYN-04** -- Language tags that are not well-formed BCP 47. *Why:* Label lookup by language silently misses them.
- **SYN-05** -- rdf:List structures used by owl:unionOf/intersectionOf/oneOf/members/propertyChainAxiom that are unterminated, branching or cyclic. *Why:* The OWL mapping to triples fails; the axiom is dropped or misread without warning.
- **SYN-06** -- owl:Restriction without owl:onProperty, or with zero or several fillers/cardinalities. *Why:* The restriction cannot be mapped to an OWL axiom and is ignored by reasoners.
- **SYN-07** -- Ontology or term IRIs ending in .owl/.ttl/.rdf. *Why:* Ties identity to a serialisation; breaks when the file format changes. *(refs: OOPS P36)*
- **SYN-08** -- Labels, definitions or comments that are empty, whitespace-only or padded. *Why:* Produces blank UI entries and duplicate-label false negatives.

- **DECL-01** -- An IRI used as a class (subject/object of rdfs:subClassOf, rdf:type object, restriction filler) that is never declared owl:Class / rdfs:Class. *Why:* Its type stays implicit; tools that enumerate the vocabulary cannot see it. *(refs: OOPS P34)*
- **DECL-02** -- A predicate or restriction property used but never declared as an object, datatype or annotation property. *Why:* A DL parser must guess the property kind, and different parsers guess differently. *(refs: OOPS P35)*
- **DECL-03** -- No owl:Ontology node, or more than one in a single document. *Why:* Without a header there is nothing to version, import or attach metadata to. *(refs: OOPS P38)*
- **DECL-04** -- Terms in the rdf:/rdfs:/owl:/xsd: namespaces that those vocabularies do not define (owl:class, rdfs:subclassOf, owl:ObjectProperties). *Why:* The single most common silent error: the triple parses, means nothing, and the intended axiom is simply absent.
- **DECL-05** -- Axioms (not annotations) asserted about terms in namespaces the ontology does not own: reserved vocabularies, or imported ontologies. *Why:* Changes the meaning of somebody else's term for every consumer that imports this ontology. *(refs: OOPS P40 · params: `owned_namespaces=from config`)*
- **DECL-06** -- Own terms minted under several base namespaces, or no stable base at all. *Why:* Consumers cannot tell which terms the ontology is authoritative for. *(refs: OOPS P39)*
- **DECL-07** -- owl:imports targets that cannot be fetched or resolved via the catalogue. *Why:* The imports closure, and therefore every reasoning result, is incomplete.
- **DECL-08** -- IRIs from a foreign namespace used in axioms when that ontology is not imported. *Why:* The reasoner treats them as fresh, unconstrained symbols.
- **DECL-09** -- One IRI typed as two of owl:Class, owl:ObjectProperty, owl:DatatypeProperty, owl:AnnotationProperty, owl:NamedIndividual without a declared punning intent. *Why:* Kind conflicts are either illegal (property kinds) or accidental punning.

- **RSN-01** -- The ontology (with imports closure) has no model: owl:Nothing has an instance, or a clash is derived. *Why:* Everything is entailed; no other result can be trusted until this is fixed.
- **RSN-02** -- A named class entailed to be equivalent to owl:Nothing; reported as root or derived (derived = unsatisfiable only because it uses a root one). *Why:* An unsatisfiable class can never have instances -- a modelling error with certainty. Root/derived separation usually turns 40 findings into 2 causes.
- **RSN-03** -- Two named classes entailed equivalent though no equivalence is asserted (includes collapse caused by subsumption cycles). *Why:* Almost never intended; silently merges two categories for every query. *(refs: OOPS P31)*
- **RSN-04** -- An entity whose inferred type comes only from a property's domain/range and is not subsumed by any asserted type. *Why:* rdfs:domain is an inference rule, not a constraint. This is how 'Locomotive' becomes a 'Person' because someone used hasDriver on it.
- **RSN-05** -- Subsumptions entailed but not asserted, flagged when they connect different top-level branches. *Why:* Inferred hierarchy changes inside a branch are often the point of defined classes; across branches they are usually an error.
- **RSN-06** -- Functional / inverse-functional properties or owl:hasKey entail owl:sameAs between individuals asserted owl:differentFrom (or under the UNA policy). *Why:* A precise diagnosis for one of the most common sources of RSN-01.
- **RSN-07** -- An asserted axiom that is entailed by the remaining axioms. *Why:* Redundancy is not wrong, but it hides intent and breaks when the other axioms change.
- **RSN-08** -- The reasoner timed out, or only OWL 2 RL reasoning ran on an ontology outside RL. *Why:* A clean RSN result from an incomplete reasoner is not evidence of absence; the report must say so.
- **RSN-09** -- Minimal axiom sets (justifications) for each RSN-01/02/03 finding, computed by black-box expand-shrink inside the STAR locality module of the entailment's signature. *Why:* A finding without its justification costs a reviewer an afternoon; with it, a minute.

- **HIER-01** -- A strongly connected component of size > 1 in the asserted rdfs:subClassOf graph. *Why:* A cycle forces every member equivalent and collapses the taxonomy under a reasoner. *(refs: OOPS P06)*
- **HIER-02** -- rdfs:subClassOf with a named individual on either side. *Why:* A category error: the author meant rdf:type.
- **HIER-03** -- rdfs:subClassOf whose object is typed as a property, datatype, ontology, skos:Concept or skos:ConceptScheme. *Why:* The axiom is meaningless or punned; either way not what was meant.
- **HIER-04** -- A ⊑ C asserted when A ⊑ B ⊑ C is also asserted (not in the transitive reduction). *Why:* Redundant edges survive refactoring of the middle class and then encode a stale claim.
- **HIER-05** -- A owl:disjointWith B (or AllDisjointClasses) where A is a descendant of B. *Why:* A becomes unsatisfiable; cheap structural diagnosis that names the cause directly.
- **HIER-06** -- A class with two ancestors that are asserted disjoint. *Why:* Unsatisfiable by construction; the structural explanation of an RSN-02 finding.
- **HIER-07** -- A subclass restriction incompatible with an inherited one (max n vs min m > n on the same property; someValuesFrom D under allValuesFrom E with D disjoint E). *Why:* Explains unsatisfiability in terms the author wrote, without a DL reasoner.
- **HIER-08** -- Sibling classes under a common parent with no disjointness axiom among them. *Why:* Without disjointness most modelling errors stay satisfiable and invisible to the reasoner. Waivable for vocabularies and thesauri (policy W1). *(refs: OOPS P10)*
- **HIER-09** -- A primitive class with two or more asserted named superclasses. *Why:* Normalisation keeps the asserted hierarchy a tree and lets the reasoner build the polyhierarchy; asserted multiple inheritance is a maintenance trap. Intentional multi-axis classification is legitimate, hence adjudication. *(refs: Rector 2003 normalisation; Arp/Smith/Spear 2015 single inheritance)*
- **HIER-10** -- A class with no asserted superclass other than owl:Thing that is not a declared top-level class, in an ontology that has a root. *Why:* Usually a forgotten placement; unconnected elements are invisible to browsing. *(refs: OOPS P04 · params: `top_level=from config or inferred`)*
- **HIER-11** -- A class with exactly one direct subclass. *Why:* Either the siblings are missing or the level adds nothing.
- **HIER-12** -- Branches deeper than a threshold, or depth far above the ontology's median. *Why:* Over-specialisation; a sign of encoding attributes as classes. *(refs: OOPS P17 · params: `max_depth=12`)*
- **HIER-13** -- A class with more direct subclasses than a threshold. *Why:* Missing intermediate categories; also unreviewable. *(params: `max_children=25`)*
- **HIER-14** -- More top-level classes than a threshold. *Why:* A fragmented taxonomy: the ontology is several ontologies, or lacks an upper level. *(params: `max_roots=10`)*
- **HIER-15** -- A top-level class that does not descend from an approved upper-ontology class (BFO, gist, DOLCE, or the house upper model) when policy requires alignment. *Why:* Alignment is what makes two domain ontologies composable. *(params: `upper=from policy`)*
- **HIER-16** -- Subsumptions whose labels suggest part-of, role, constitution or membership (Wheel ⊑ Car, Driver ⊑ Locomotive). *Why:* Using subClassOf for every relation is the most common taxonomic error by novices. *(refs: OOPS P03)*
- **HIER-17** -- Leaf classes whose labels are proper names or unique artefacts (Germany, ISO 8601, the Class 66 locomotive #66001). *Why:* Instances modelled as classes cannot carry facts as individuals.
- **HIER-18** -- An anti-rigid class (role, phase) subsuming a rigid one, and other OntoClean meta-property violations, where meta-properties are annotated (or proposed by the LLM and confirmed by a human). *Why:* Student ⊑ Person is fine; Person ⊑ Student is not -- OntoClean makes the difference checkable. *(refs: OntoClean, Guarino & Welty)*
- **HIER-19** -- skos:broader between owl:Classes, or rdfs:subClassOf between skos:Concepts. *Why:* Mixes an associative navigation relation with logical subsumption.
- **HIER-20** -- A ≡ B together with A ⊑ B (or B ⊑ A) asserted. *Why:* The subsumption is redundant and suggests the author doubted the equivalence.
- **HIER-21** -- Sibling classes with identical superclass sets and no distinguishing restriction, definition or annotation (no differentia). *Why:* Aristotelian definition: genus plus differentia. Siblings without differentia are duplicates or undefined. *(refs: Arp/Smith/Spear 2015)*
- **HIER-22** -- A child whose label's head noun is unrelated to the parent's (Locomotive ⊑ Signal). *Why:* Cheap lexical signal of a misplaced class; noisy, hence adjudication.
- **HIER-23** -- A non-deprecated class whose asserted parent is owl:deprecated. *Why:* Children of a deprecated class inherit its retirement without anyone deciding so.

- **PHIER-01** -- Cycle in rdfs:subPropertyOf. *Why:* Collapses the properties into equivalents.
- **PHIER-02** -- A sub-property whose domain/range is not subsumed by its super-property's. *Why:* Every use of the sub-property infers the super-property's domain anyway; the declared narrower intent is contradicted or the wider one leaks.
- **PHIER-03** -- p owl:inverseOf q where domain(p) is not range(q) or range(p) is not domain(q). *Why:* Wrong inverses produce silent type inferences on every use. *(refs: OOPS P05)*
- **PHIER-04** -- p owl:inverseOf p. *Why:* Means symmetric; say owl:SymmetricProperty. *(refs: OOPS P25)*
- **PHIER-05** -- An inverse declared for a property that is symmetric. *Why:* Redundant and usually a sign of confusion about the property's meaning. *(refs: OOPS P26)*
- **PHIER-06** -- An object property sub-property of a datatype property or vice versa. *Why:* Illegal in OWL 2 DL.
- **PHIER-07** -- Object properties without a declared inverse where policy requires one. *Why:* Queries in the reverse direction cannot be written in the vocabulary. *(refs: OOPS P13)*
- **PHIER-08** -- owl:propertyChainAxiom with one element. *Why:* That is a sub-property axiom written the hard way. *(refs: OOPS P33)*

| PROP-03 | **Range kind mismatch** | blocker | sparql | none | owl | S1b | datatype-range-on-object-property |
| PROP-04 | **Conflicting characteristics** | major | sparql | none | owl | S1b | symmetric-and-asymmetric |
| PROP-05 | **Symmetric property with distinct domain and range** | major | sparql | none | owl | S1b | symmetric-with-distinct-range |

| PROP-07 | **Unused property** | info | sparql | none | owl | S1b | declare-unused-property |

| PROP-09 | **Literal-valued object property in use** | major | sparql | none | abox | S1b | literal-on-object-property |

- **PROP-01** -- Object (and datatype) properties lacking rdfs:domain or rdfs:range. *Why:* Without them the property carries no commitment and a reasoner infers nothing. *(refs: OOPS P11)*
- **PROP-02** -- More than one rdfs:domain (or range) asserted for a property. *Why:* Multiple domains mean the intersection; the author almost always meant the union. *(refs: OOPS P19)*
- **PROP-03** -- Object property with a datatype range, or datatype property with a class range. *Why:* Illegal in OWL 2 DL; meaningless in RDFS.
- **PROP-04** -- Symmetric + asymmetric, reflexive + irreflexive, asymmetric with a reflexive super-property; functional + transitive flagged as suspicious. *Why:* Either unsatisfiable usage or a misunderstanding of the characteristic.
- **PROP-05** -- A symmetric property whose domain and range differ. *Why:* Symmetry forces every subject into the range and vice versa. *(refs: OOPS P28)*
- **PROP-06** -- Transitive properties whose names denote non-transitive relations (hasParent, isAdjacentTo, hasDirectPart). *Why:* A wrong transitivity floods the closure with false facts. *(refs: OOPS P29)*
- **PROP-07** -- A declared property never used in an axiom, restriction or assertion. *Why:* Dead vocabulary, or a missing restriction.
- **PROP-08** -- owl:equivalentProperty between properties with incompatible domains/ranges. *Why:* The equivalence silently retypes every use of either property. *(refs: OOPS P27)*
- **PROP-09** -- An object property asserted with a literal object, or a datatype property with an IRI. *Why:* Data and vocabulary disagree on what the property is.
